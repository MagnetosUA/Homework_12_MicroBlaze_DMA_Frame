# Homework 12 — MicroBlaze DMA Frame Capture

Frame capture system based on MicroBlaze, AXI DMA and BRAM.

## Task

The design receives an external frame with the following parameters:

- Resolution: `320 x 200`
- Pixel size: `8 bit`
- Frame size: `64,000 bytes`
- AXI4-Stream width: `32 bit`
- AXI words per frame: `16,000`

Capture starts only after a button press handled by MicroBlaze.

---

## Architecture

```text
External 8-bit data
        |
        v
 frame_rx_axis
        |
        v
 Async FIFO
   8-bit -> 32-bit
        |
        v
 AXI4-Stream
        |
        v
 AXI DMA S2MM
        |
        v
 AXI BRAM Controller
        |
        v
 64 KiB BRAM
```

Control path:

```text
Button
  |
  v
AXI GPIO
  |
  v
MicroBlaze
  |
  v
GPIO Channel 2
  |
  v
START
```

## Main Components

- MicroBlaze
- AXI GPIO

- AXI BRAM Controller
- Block Memory Generator
- Custom `frame_rx_axis` RTL module
- Asynchronous FIFO
- Vitis standalone application
- XSim behavioral testbench

---

## Frame Receiver

The custom `frame_rx_axis` module:

- waits for the `start` signal
- receives exactly `64,000` bytes
- uses an asynchronous FIFO for clock-domain crossing
- converts `8-bit` input data to `32-bit`
- outputs data through AXI4-Stream
- generates `TLAST` on the final AXI word

The FIFO converts four 8-bit pixels into one 32-bit AXI word.

---

## DMA Configuration

The AXI DMA is configured in S2MM mode only.

```text
Destination address: 0xC0000000
Transfer size:       64000 bytes
BRAM size:           64 KiB
AXI words:           16000
```

---

## MicroBlaze Software

The MicroBlaze application:

1. waits for the button press
2. configures the DMA S2MM transfer
3. generates the `start` pulse through AXI GPIO Channel 2
4. waits for DMA completion

## Simulation Results

### Full Frame Capture

![Full Frame Capture](screenshots/01_full_waveform.png)

The waveform shows the complete control sequence:

```text
Button
  -> AXI GPIO
  -> MicroBlaze
  -> GPIO Channel 2
  -> START
  -> Frame Capture
  -> AXI4-Stream
  -> AXI DMA
```

The simulation confirms that frame capture starts only after the button press and the `start` signal generated by MicroBlaze.

---

### End of Frame

![Frame Counters and TLAST](screenshots/02_frame_counters.png)

The final AXI4-Stream transfer is identified by:

```text
word_count = 15999
m_axis_tvalid = 1
m_axis_tready = 1
m_axis_tlast = 1
```

The complete frame contains:

```text
16000 x 32-bit words
```

which corresponds to:

```text
64000 bytes
```

or exactly:

```text
320 x 200 pixels
```

---

### BRAM Write

![BRAM Write](screenshots/03_bram_write.png)

The waveform confirms that AXI DMA writes the received 32-bit data into BRAM through the AXI BRAM Controller.

The following BRAM signals are visible during the transfer:

- `bram_addr_a`
- `bram_wrdata_a`
- `bram_we_a`
- `bram_en_a`
